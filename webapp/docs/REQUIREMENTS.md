# 体育舞蹈赛事评分系统 · 服务版需求规格（REQUIREMENTS）

> 版本：v0.2.4（GC 解冻实现：Q-R1~R4 拍板值落为 D10~D13；P-1/P-2/P-3 提案不纳入本次实现（M1→M5）；实现启动）
> 日期：2026-08-27
> 依据：main 分支桌面版 `Readme.md` 功能清单、`src/ui` 各选项卡体现的领域流程、用户已表达诉求（多设备访问、裁判移动端评分、实时成绩大屏、局域网部署）。
> 说明：本服务版从 main 重新开发，UI/交互全新设计；**不参考任何旧 web 实现结构**。

---

## 1. 背景与目标

现有桌面版（tkinter）为单机应用：管理员在一台电脑上完成赛事创建、数据导入、评分录入、晋级处理与结果导出。服务版将其演进为**局域网 Web 服务**：

| 目标 | 说明 |
|------|------|
| 多设备访问 | 管理员、裁判、观众用各自设备（电脑/手机/平板）通过浏览器访问 |
| 裁判移动端评分 | 裁判在手机上完成顺位/Mark 评分提交，替代纸质评分表 |
| 实时成绩大屏 | 现场大屏/观众手机实时展示进行中场次与已产生的成绩 |
| 局域网部署 | 单台轻量服务器（**1.6G RAM**）部署，无外网依赖 |

## 2. 用户与角色

| 角色 | 说明 | 主要操作 |
|------|------|----------|
| 管理员（Admin） | 赛事组织者/计裁判长 | 赛事管理、数据导入、赛程管理、评分监控、晋级确认、结果发布与导出 |
| 裁判（Judge） | 持裁判 ID 的临场评委 | 在自己设备上对本场次选手提交顺位/Mark 评分 |
| 观众（Spectator） | 现场观众/大屏 | 只读查看赛程、实时成绩、名次榜 |

> 账号体系（已拍板，DECISIONS D2）：管理员口令登录 + 裁判凭裁判 ID 登录（可配置裁判口令）+ 观众免登录。
> ⚠️ 部署约束（已拍板，D1/D9）：服务器可从外网访问——管理员/裁判端必须登录+会话，公开页只读，登录接口防爆破，使用非默认高位端口（见 DESIGN「外网暴露对策」）。

## 3. 领域流程（源自桌面版领域逻辑，交互载体改为 Web）

### 3.1 赛事管理（源：赛事管理选项卡）
- FR-A1 创建赛事：名称、日期、地点；系统生成赛事数据目录。
- FR-A2 打开/切换赛事：支持多赛事管理；但**同一时间至多一个赛事处于运行流程（"激活"语义）**——激活赛事方可开场评分/计算/晋级，其余赛事仅可查看与编辑基础数据（D6）。
- FR-A3 删除赛事、导出目录设置。

### 3.2 数据导入（源：数据导入选项卡）
- FR-B1 选手导入：CSV/Excel，列＝背番号｜项目编号｜姓名｜学校/单位。
- FR-B2 赛程导入：列＝场次编号｜场次名称｜项目编号｜轮次｜舞种｜评分类型（SKATING/MARK）｜晋级人数｜参赛选手（仅第 1 轮填写，逗号分隔）。
- FR-B3 裁判导入：列＝裁判 ID｜姓名。
- FR-B4 批量导入：按文件名关键字（competitor/选手、schedule/赛程、judge/裁判）一次导入目录。
- FR-B5 导入后自动生成第 1 轮各场次评分表（选手列表已确定）。
- FR-B6 导入预览与校验反馈（格式/缺列/编码错误明确提示）。

### 3.3 评分（源：赛程管理 + 独立评分窗口；服务版改为裁判移动端提交）
- FR-C1 场次开始：管理员开启某场次评分，指定本场上场选手（可剔除未到场选手；已有评分数据时清空重开）。
- FR-C2 裁判评分（顺位法）：对上场全部选手给出 1~N 唯一名次；提交前客户端校验完整性。
- FR-C3 裁判评分（Mark制）：对上场选手逐个给出布尔标记（mark=是/否，即"标记通过"票）；系统按各选手获得的标记票数排名（与 core/ 的 ScoreRecord.mark: Optional[bool] 语义一致）。
  > 注：main 桌面版 Readme §4.2 将 Mark制描述为"0-10 分打分取均值"，但 core/ 内核实现为布尔标记票制；本需求按 core 实现语义书写。若用户确认需要 0-10 分制，须扩展 core 算法，见 §8 残余开放问题 Q-R2。
- FR-C4 分舞种评分：一场次含多舞种时按舞种分别提交。
- FR-C5 修改/重交/退回：场次未关闭前允许裁判修改自己的评分；管理员可**退回**某裁判的评分要求重交。
- FR-C6 完成判定与自动计算：全部裁判全部舞种提交后，系统**默认自动触发场次计算**（D3）；管理员保留手动触发与重算能力。
- FR-C7 评分作废：管理员可将某裁判在某场次的评分**作废**（计入审计日志；作废后该裁判须重新提交才满足收齐条件）。

### 3.4 计算与晋级（源：晋级确认窗口；算法内核＝core/）
- FR-D1 场次结果计算：分舞种结果 + 综合结果（core/，与桌面版逐位等价）。
- FR-D2 晋级计算：按赛程晋级人数与晋级规则（all_tied_advance / strict_count）。
- FR-D3 自动触发：某项目本轮全部场次完成后提示晋级确认。
- FR-D4 晋级确认页：展示本轮各组结果、合并晋级名单、下一轮名单；**管理员可手动调整**后确认。
- FR-D5 确认后自动填充下一轮场次参赛名单。
- FR-D6 多组半决赛合并晋级（蛇形/随机分组到下一轮场次）。

### 3.5 结果与发布（源：结果查看选项卡）
- FR-E1 结果类型：分舞种结果、综合结果、评分明细（含滑冰法区间/决胜明细）、综合名次表（决赛）。
- FR-E2 导出（D8）：Markdown 导出 + **打印友好 HTML**（用浏览器自带"打印/另存为 PDF"）；**不做服务端重依赖 PDF 生成**。
- FR-E3 发布：管理员将场次/项目结果"发布"到大屏与观众页；**发布内容不含评分明细**（D5）；三态生命周期（draft/公示/正式）见 FR-E6 与 DESIGN §6.2。
- FR-E4 明细权限：评分明细（含滑冰法区间/决胜明细）**仅管理端可查询**；观众页与大屏不提供明细（D5）。
- FR-E5 观众页：按项目查看已发布名次榜。

### 3.6 实时大屏（新增诉求）
- FR-F1 大屏页：当前进行中场次、已完成场次成绩滚动、颁奖台/名次榜；默认自动轮播，内容跟随赛程（进行中场次 → 已出成绩 → 名次榜）（D4）。
- FR-F2 成绩产生/发布后数秒内自动刷新（方案见 DESIGN §7）。
- FR-F3 大屏管理（D4）：管理员可暂停/切换/指定大屏画面。

### 3.7 管理员控制面（R-4，全场全要素控制）
管理员对以下要素拥有端到端控制能力（API 对应见 DESIGN §4.1）：
- FR-G1 赛事全生命周期管理：创建/打开/激活/删除/设置（FR-A1~A3 的控制面归集）。
- FR-G2 数据导入：选手/赛程/裁判/批量导入与校验报告（FR-B1~B6）。
- FR-G3 场次开场/关闭/重开：含上场选手重置（清空已有评分）。
- FR-G4 上场选手增删：开场前及评分中调整上场名单（评分中调整须清空该场次评分并二次确认）。
- FR-G5 评分退回/作废：退回某裁判评分要求重交（FR-C5）、作废评分（FR-C7）。
- FR-G6 计算与重算：手动触发/重算场次结果（FR-C6/D1）。
- FR-G7 晋级预案调整：晋级确认页手动调整名单后确认（FR-D4）。
- FR-G8 结果发布/撤回：发布到大屏与观众页，也可**撤回**已发布结果（FR-E3）。
- FR-G9 大屏内容强制切换：暂停/切换/指定大屏画面（FR-F3）。
- FR-G10 数据导出与备份：导出 HTML/Markdown、触发备份（FR-E2、NFR-6）。

### 3.8 实时性与适配（R-1/R-2/R-3）
- FR-H1 响应式适配：全部页面双端适配——裁判页**移动优先**；管理页**桌面优先、平板可用**；观众页自适应；大屏页专为横屏大屏设计（适配策略逐页标注见 DESIGN §3）。
- FR-H2 裁判端高实时性：开场/换场、上场名单变化、其他裁判提交进度须**秒级**到达裁判端（事件到达延迟目标 **<2s**，方案见 DESIGN §7）。
- FR-H3 管理端状态快速同步：全部管理页面（赛程总览、场次控制台、晋级确认、结果中心）的状态变化（裁判提交、计算完成、发布等）自动快速同步，**不得依赖手动刷新**（与 FR-H2 共用 SSE 通道、按事件分组订阅）。

### 3.9 集体项目与团体总分（用户追加，结合大型赛事通行实践）

> 领域调研结论（来源：WDSF 竞赛规则对 Formation/队列舞的通行规定、国内体育舞蹈赛事（中国体育舞蹈联合会系列赛、大学生锦标赛等）团体总分惯例——公开规则通行实践梳理，实现前建议对照具体赛事章程原文复核。注：以上为模型知识梳理、未经网络实时核验——本环境 web 检索结果页不可用）：
> - **集体项目（Formation，集体舞/队列舞）**：一般 6~8 名选手（替补 ≤2）成队，以**队伍**为参赛单元整体上场；裁判对队伍整体按顺位法或 Mark 制评分，晋级亦以队伍为单位。评分算法与 Couple 项目同构（"队"即一个评分对象/编号）。
> - **团体总分**：非独立参赛项目，而是赛后**聚合口径**——各单位按其选手/队伍在各级别项目的名次折算积分排名。通行口径两类：①**按名次赋分**（如前 8 名 9-7-6-5-4-3-2-1，通常只对决赛/最终名次赋分）；②**累计小分**（直接累计成绩或序和）。常见附加规则：只取每单位**最佳 N 项**、分组别分别排名或设权重、双人跨单位组合的归属特殊处理。
- FR-I1 项目类型扩展：项目（project）区分 `couple`（单人/双人）与 `formation`（集体：集体舞、队列舞等）；团体总分为**聚合口径**而非参赛项目。
- FR-I2 集体项目报名组队模型：一支集体队伍 = 所属单位（唯一）+ 队名 + 队员名单（含替补）；队伍整体获得一个背番号，作为评分与晋级的最小单元。
- FR-I3 跨单位舞伴：couple 双人项目允许两名选手来自**不同单位**；其成绩的团体归属口径见开放问题 Q-R4（不替用户拍板）。
- FR-I4 队伍同单位约束校验：**一队一单位**为校验规则——集体/团体队伍全体队员必须同属一个单位；报名/导入时校验，违规拒绝并明确报出违规队员。
- FR-I5 集体项目评分与晋级：与 Couple 项目使用同一套评分类型（顺位法/Mark制）与晋级规则；裁判对队伍整体打分，计算/晋级均以队伍为单位（算法上"队伍＝一个编号"）。
- FR-I6 团体总分计算：按赛事配置的口径聚合各单位成绩生成团体总分榜（口径选项见开放问题 Q-R3）；支持分组别统计。
- FR-I8（提案）团体总分口径多方案与重算：提案，待用户确认，详见附录 P-1。
- FR-I7 团体总分发布：团体总分榜可发布至管理端、观众页与大屏（沿用发布制 D5）。
- FR-E6（提案）结果发布三态分离：提案，待用户确认，详见附录 P-2。
- FR-J1（提案）复制上届建赛：提案，待用户确认，详见附录 P-3。
- FR-J2 动线极简原则：管理员/裁判/观众三条核心动线（见 DESIGN §2.4）之外的功能收进"管理高级区"，不为边界功能增加主界面复杂度。

## 5. 约束与边界
- 算法以 worktree 内 `core/`（feat/service-core）为唯一内核，服务层只做编排不改算法；**新增算法能力（如团体总分聚合）设计为 core 的独立新增模块，不修改现有算法文件，等价性基线不被触碰**。
- 服务端不做重依赖 PDF 生成（D8）；不做支付/报名收费、不做视频直播。
- 数据格式完全重做（D7）：提供**一次性迁移工具**（独立小工具，非服务端功能），以旧桌面版 JSON 为 source 转入新格式。

## 6. 验收要点（对应 FR 摘要）
1. 从创建赛事到导出决赛综合名次表的全流程可在纯浏览器完成。
2. 两台手机（裁判）+ 一台管理机 + 一台大屏同局域网并发演示顺畅。
3. 任一场次的计算结果与桌面版对同一输入的结果完全一致。
4. 评分收齐后无需人工操作即自动出结果（D3）；大屏可由管理员暂停/切换（D4）。
5. 观众/大屏无法访问任何评分明细 URL（D5）。
6. 管理员开场→裁判端 <2s 收到评分表（FR-H2）；管理页状态变化无手动刷新即更新（FR-H3）。
7. 控制面全项操作可达且生效（FR-G1~G10），含撤回已发布结果与作废评分。

### P-1 团体总分口径多方案与重算（对应 FR-I8（提案））
支持保存**多套命名口径方案**（named presets）；管理员切换方案后**即时重算**——聚合为纯函数、重算幂等、不重复入账；每次重算记录**配置快照与时间**，历史可追溯；口径可按赛事/项目各自绑定。机制不预设口径内容（Q-R3 仍由用户拍板）。

### P-2 结果发布三态分离（对应 FR-E6（提案））

### P-3 复制上届建赛（对应 FR-J1（提案））
新建赛事支持**复制上届**（复制单位/选手/项目/赛程模板结构）；配合项目单页一步完成与轮次批量生成。
