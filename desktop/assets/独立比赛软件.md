# 体育舞蹈赛事独立打分软件设计文档（简化版）

## 1. 产品概述

### 1.1 产品定位
体育舞蹈赛事独立打分软件是一款基于背番号的专业赛事评分工具，支持Mark制（淘汰法）和顺位法（Skating System）两种评分方式。软件设计为独立可执行文件（exe），可在Windows系统上双击运行，无需安装额外依赖。

### 1.2 核心价值
- **简化赛事管理**：一站式管理从选手导入到成绩输出的完整流程
- **标准化评分**：严格遵循国际体育舞蹈评分规则
- **独立运行**：无需网络连接和服务器支持
- **数据安全**：本地数据存储，确保赛事数据不外泄
- **多舞种支持**：完整支持多舞种综合评分和排名

### 1.3 适用场景
- 学校体育舞蹈比赛
- 地区性体育舞蹈赛事
- 小型至中型专业体育舞蹈比赛
- 无稳定网络环境的比赛场地

## 2. 功能需求

### 2.1 数据导入与管理

#### 2.1.1 选手信息导入
- **目录导入**：
  - 选择包含数据文件的目录
  - 自动识别并导入选手数据文件（如test_competitors.csv）
  - 支持常见文件名模式识别
- **人工添加**：支持手动添加单个选手信息
- **数据验证**：自动检查背番号唯一性和格式正确性

#### 2.1.2 赛程表导入
- **目录导入**：
  - 选择包含数据文件的目录
  - 自动识别并导入赛程数据文件（如test_schedule.csv）
  - 支持常见文件名模式识别
- **赛程解析**：自动识别场次间依赖关系
- **人工编辑**：支持手动调整赛程安排

### 2.2 比赛管理

#### 2.2.1 场次控制
- **场次选择**：从赛程表中选择当前进行的场次
- **状态管理**：场次状态（未开始/进行中/已完成）
- **多舞种管理**：支持单场次多舞种评分

#### 2.2.2 评分输入
- **简化裁判管理**：
  - 每条评分记录关联一个裁判ID（可缺省姓名）
  - 支持动态添加裁判（无需预先导入）
  - 裁判编号自动生成（J1, J2, J3...）

- **评分表格界面**：
  - 表格格式：背番号为列，舞种为行
  - Mark制表格：每个单元格为复选框（勾选表示获得Mark）
  - 顺位制表格：每个单元格为数字输入框（输入名次）
  - 不显示选手具体信息，仅显示背番号
  - 表格顶部显示场次信息和舞种列表

- **表格操作功能**：
  - 自动保存：每次输入后自动保存评分记录
  - 评分验证：检查评分完整性和合法性
  - 快速导航：支持键盘快捷键在单元格间切换
  - 批量操作：支持一键清空或重置表格

### 2.3 结果计算与输出

#### 2.3.1 非决赛场次处理（Mark制）
- **多舞种综合晋级**：
  - **累计Mark晋级模式**：
    - 各舞分别记录Mark数量，按选手在本轮所含全部舞的Mark进行累计
    - 按累计Mark从高到低排序
    - 根据预设晋级名额确定晋级选手
    - **同分处理规则**：
      - 当第N名与第N+1名Mark相同时，同时晋级，确保公平性
      - 允许因同分增加晋级人数，不强制限制晋级名额

- **下一轮次导入**：
  - 提供"导入晋级名单"按钮
  - 自动查找相同项目编号的后续轮次
  - 将晋级选手背番号导入到下一轮次的参赛选手列表
  - 支持手动调整和确认

- **结果输出**：
  - 晋级名单打印（包含Mark统计）
  - 本轮次评分明细导出
  - 晋级选手背番号列表（用于下一轮次导入）
  - **下一轮次打分表格输出**：
    - 自动生成下一轮次的空白打分表格
    - 表格格式与评分输入界面一致（背番号为列，舞种为行）
    - 支持打印和导出为Excel/CSV格式
    - 可选择包含裁判信息栏（裁判ID和姓名）

#### 2.3.2 决赛场次处理（顺位法）
- **多舞种综合排名**：
  - **步骤1：逐舞产生名次**
    - 每支舞独立应用顺位法（Skating System）
    - 得到该舞的赛事名次（1-N）
    - 保留裁判顺位、多数票、分数总和等判定过程

  - **步骤2：综合总排名（序和法）**
    - 将每对选手在所有舞的名次进行"序和"相加
    - 序和越小，总排名越靠前
    - 并列处理规则：
      1) 多数裁决：比较更靠前名次的出现多数
      2) 最佳名次比较：比较最佳名次的数量与层级
      3) 裁判分数总和比较（更低者靠前）
      4) 无法区分时，采用并列名次

- **成绩单生成**：
  - 标准成绩单格式
  - 包含详细评分明细
  - 支持自定义格式

- **结果保存**：
  - 比赛结果永久保存
  - 支持历史成绩查询
  - 数据导出功能

## 3. 技术规格

### 3.1 技术栈
- **前端界面**：Tkinter（Python内置GUI库）
- **后端逻辑**：Python 3.12+
- **数据处理**：pandas（Excel/CSV处理）
- **打包工具**：PyInstaller（生成独立exe文件）

### 3.2 数据存储（优化版）
- **文件存储**：使用JSON文件存储所有数据，统一数据格式
- **赛事隔离**：每个赛事创建独立文件夹，确保数据完全隔离
- **简化数据结构**：
  - 赛事文件夹（以赛事名称+日期命名，如"2024高校赛_20240515"）：
    - 赛事数据文件（event.json）：包含选手、赛程、评分和结果数据
    - 备份文件（event_backup.json）：自动备份的数据文件
  - 应用配置文件（config.json，位于应用根目录）：
    - 当前打开的赛事路径
    - 最近打开的赛事列表

### 3.3 评分算法（优化版）
- **Mark制算法**：统计每位选手获得的Mark数量，按数量排序
- **顺位法算法**：实现核心Skating System算法，处理多数裁决和分数总和
- **多舞种综合算法**：
  - Mark制：累计各舞种Mark数量，按总数排序
  - 顺位法：计算序和，按序和排序，处理并列情况

### 3.4 系统要求
- **操作系统**：Windows 7/8/10/11（64位）
- **硬件要求**：1GB RAM，50MB可用磁盘空间
- **运行环境**：无需安装Python或其他依赖

## 7. 多舞种评分实现细节

### 7.1 数据模型
- **场次-舞种关系**：
  - 每个场次可包含多个舞种
  - 舞种以逗号分隔的字符串存储（如"W,T,VW"）
  - 系统自动解析为舞种列表

- **评分数据结构**：
  ```json
  {
    "event_id": "1",
    "judge_id": "J1",
    "judge_name": "裁判1",
    "score_type": "mark",  // "mark" 或 "ranking"
    "dance_scores": {
      "W": {
        "33": true,  // Mark制：true/false表示是否获得Mark
        "80": false
      },
      "T": {
        "33": 1,  // 顺位制：数字表示排名
        "80": 2
      }
    }
  }
  ```

- **表格显示逻辑**：
  - 行：舞种（按场次定义的舞种顺序）
  - 列：参赛选手背番号（按数字顺序）
  - 单元格：根据评分类型显示复选框或数字输入框

### 7.2 Mark制多舞种综合
- **累计Mark计算**：
  - 遍历所有舞种，累计每个选手获得的Mark数量
  - 缺席某舞视为该舞Mark为0
  - 按累计Mark从高到低排序

- **同分处理**：
  - 当第N名与第N+1名Mark相同时，同时晋级
  - 允许因同分增加晋级人数，不强制限制晋级名额
  - 确保评分公平性，避免因同分导致的争议

### 7.3 顺位法多舞种综合
- **逐舞排名计算**：
  - 对每个舞种独立应用Skating System算法
  - 计算每个舞种的排名结果
  - 保存排名过程和判定依据

- **序和法总排名**：
  - 计算每个选手在所有舞种的序和
  - 按序和从小到大排序
  - 处理并列情况
