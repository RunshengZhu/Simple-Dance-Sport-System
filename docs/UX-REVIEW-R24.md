# UX 严苛 Review 与整改方案 R24（2026-09-06）

> 视角：多类用户使用便利性（管理员/裁判×习惯差异/观众/大屏）+ 页面空间充分利用。
> 方法：逐页面代码级走查 + R21/R23 E2E 实测观察。循环协议：Review → 整改 → 验证 → 再 Review，直至收敛。

## 第一轮 Review 发现（F=Finding）

### 裁判动线
- **F1 (P0，用户明确要求) 顺位法只支持一种打分习惯**。R23 的顺序点选对「按 1→N 顺序打分」的裁判友好，
  但「先看全场、直接给每个背号赋名次」的裁判没有顺手的方式（顺序点选强制先点第 1 名）。
  → 整改：双模式切换「顺序点选 / 直接指定」。指定模式=点选选手行 + 底部名次键盘（已占用名次禁用，
  点自己的名次键取消），两模式共享同一份状态（隐藏 .val），切换不丢数据。
- **F2 (P2) 无重置手段**：全填错时只能逐个点掉。→ 整改：表单加「重置」小按钮（二次确认）。
- **F3 (P3) 进度提示不可点**：顺序模式「还差 X」没有引导到下一个动作（可接受，记为观察项）。

### 赛程管理（管理员）
- **F4 (P0，用户明确要求) 无防连场手段**：场次顺序 = 导入顺序，同一批选手可能被连续开两场（无休息）。
  → 整改：赛程页新增「比赛顺序（防连场）」面板：
  ① 「自动排序建议」——贪心算法在尊重同项目轮次依赖（R1 必须先于决赛）的前提下，
  相邻场次选手重叠最小化；② 建议列表逐行「上移/下移」手动微调；③ 相邻场次重叠人数以
  「连场 N 人」徽章实时高亮（≥1 即提醒）；④ 「保存顺序」持久化（events.run_seq），
  「清空」回到默认。自动化只出建议，编辑自由度完整保留。
- **F5 (P1) 51 场次无状态筛选**：找「评分中」的场次要滚全页。→ 整改：状态筛选 chips
  （全部/待赛/评分中/已计算/已发布）。
- **F6 (P3) 编排树顺序≠实际比赛顺序**，run_seq 保存后树内加序号徽章。

### 观众动线
- **F7 (P0，用户明确要求) 无背番号查询**：观众/领队想知道「101 号现在成绩如何」，只能逐场翻。
  → 整改：公开成绩页顶部加「按背番号查询」卡：输入背番号 → 返回公示允许的有限信息
  （姓名、单位、参赛项目、各已发布场次的名次/总分）。API：/api/public/events/{cid}/lookup。
- **F8 (P3) 公开成绩页长列表无锚点**（12+ 场次卡片堆叠）。→ 记为后续项（影响小）。

### 大屏
- **F9 (P1) 成绩公告无冠军强调**：已有 tr.rank-1 金色样式但 JS 渲染未挂 class。
  → 整改：渲染时 rank==1 行加 rank-1 class。

### 空间利用与其他
- **F10 (P2) events 页创建表单常驻展开**，历史赛事多时列表被推下去。→ 本轮暂缓（影响小，移动端更明显，记入收敛清单）。
- **F11 (P2) 导入页无 CSV 模板下载**，新用户要翻 README。→ 本轮暂缓（记入收敛清单）。
- **F12 (P3) 控制台无「同项目下一场」快捷导航**。→ 暂缓。
- **F13 (P3) 大屏 forced results 1/N 计数在弱网下可能过期**（有 SSE 刷新兜底）。→ 观察项。
