# E2E 交互走查计划 R38 —— 全角色动线实测迭代

> 目标：以"动线实际操作"为标准，对全部六类角色的每条动线在真实 UI 上逐步点击、逐步截图判读，
> 发现并修复交互精度与便捷度问题，迭代到没有明显的交互和视觉问题。
> 主持/检录页只是用户举的例子，本计划覆盖全部角色。

## 0. 已实锤的系统性缺陷（本轮先行修复，否则污染所有动线测试）

**SSE 断线回退 = 周期性整页重载（P0，全体动线）**
- base.html `autorefresh` 注入（events/schedule/import/results/advancement/teams/team_standings
  7 页）：回退轮询 `location.reload()` 每 **3 秒**。
- judge_home / judge_sheet：回退轮询 2 秒重载（裁判打分中断网 = 反复丢上下文）。
- staff：`checkin_changed → reload` 且广播含操作者自身 → 检录员每点一个背号，自己页面 5 秒内重载。
- 公开三页 5 秒重载，观众浏览中被反复拉回顶部。
- 手机上 SSE 极易断（锁屏/切后台/弱网切换）→ 重载风暴 → "点击后胡乱滚动"、点击丢失、滚动归零。

**修复原则（P0 包）**
1. 回退轮询一律禁止 `location.reload()`；改为页面注册的轻刷新（局部拉数据就地重绘），
   未注册则静默降级（静态页）。
2. 结构性事件确需重载时走 `softReload()`：sessionStorage 保存 scrollY（URL 键控 + 10s TTL），
   load 后恢复；`document.hidden` 时只置脏标记，回到前台刷一次；500ms 窗口内多事件合并。
3. 检录类高频事件（checkin_changed）全部改轻刷新：
   新端点 `GET /api/competition-events/{ceid}/checkin`（staff+judge 只读）返回 checked 列表，
   staff/judge_sheet/console 就地更新，不重载。
4. 动态重绘区域（staff chips 等）一律**事件委托**绑定，禁止逐元素绑定（重建后失灵）。

## 1. 判读标准（每一步截图逐条核对，任一不过即记录 issue）

1. 点击后视口稳定：无意外滚动跳变、无重载闪白、点击目标不被移走。
2. 每个操作有即时可见反馈（选中态/计数/提示），失败有明确报错。
3. 移动端 375 宽无水平滚动（进度矩阵 #matrix 例外）；文字无截断溢出。
4. 触控目标可命中（相邻可点元素不重叠、间距足够，chip/按钮误触率低）。
5. 关键数字（检录进度/评分进度/名次）与操作后状态一致（本地乐观更新 = 服务端返回值）。
6. 空态/异常态有引导文案，不白屏不裸报错。
7. 桌面 1440 与移动 375 双端同等可完成动线。

## 2. 角色 × 动线矩阵（每条动线逐步驱动 + 截图判读）

### A. 管理员（桌面 1440×900 主 + 移动 375 复测关键页）
- A1 登录 → 激活赛事 → events 列表（建赛、启停）。
- A2 导入花名册（CSV）→ 校验回显。
- A3 赛程编排：树形列表、生成场次、run order 防连场、状态筛选。
- A4 控制台：进度矩阵、花名册、生命周期 open→scoring→calculate→publish→unpublish→退回评分。
- A5 用户管理：建 host/marshal 账号、重置口令、停用/启用。
- A6 晋级视图 / 成绩中心 / 团体总分 / 大屏控制页浏览与切换。

### B. 检录长·检录员（移动 375×812 主，桌面复测）
- B1 登录（用户名+口令）→ 检录台头部身份显示。
- B2 场次筛选 chips（全部/待检录/已完成）+ 编号搜索；搜索命中自动定位高亮。
- B3 单点检录/撤销：点击后 chip 状态即时翻转、计数即时更新、**视口不动**。
- B4 批量：全部检录 / 全清，一次性反馈。
- B5 已完成场次：默认折叠，原位展开成绩公告（手风琴，展开一个收起其它），收起恢复。
- B6 本场成绩单下载链接可见；播报标记可切换。
- B7 断线降级：SSE 断开时无重载风暴，恢复后状态收敛。

### C. 主持人（移动 375 + 桌面）
- C1 同 B1-B7（host 登录，含播报标记主职）。
- C2 控制台联动：开场/开场后检录台状态同步（轻刷新验证）。

### D. 裁判（移动 375×812 主）
- D1 登录（口令直登）→ 工作台场次卡（状态徽章）。
- D2 Skating 顺位法：顺序点选模式 + 直接指定模式切换、整行 Mark。
- D3 Mark/Score 制：行选、数字键盘输入、吸附提交栏。
- D4 未检录行置灰不可评、缺席/未到场切换、提交守卫（缺项拦截提示）。
- D5 提交成功反馈与回显；检录变化实时置灰更新（不重载、不打断输入）。
- D6 断线降级：轮询期间**绝不重载**，输入不丢失。

### E. 观众（移动 375×812，匿名）
- E1 公开赛程页 → 成绩页 → 背号查询卡 → 团体榜。
- E2 发布后 5~10s 内自动更新（软刷新，滚动位置保持）。
- E3 无横滑、公告带选手姓名、长榜可读。

### F. 大屏（1920×1080）
- F1 四屏（欢迎/评分中/成绩/团体）切换与控制端联动。
- F2 自动刷新不断流、无半渲染帧。

## 3. 执行方法

- 环境：本地 worktree 起服务器（127.0.0.1:8301，独立 DB 副本），种子测试数据
  （多项目类型/多轮次/缺席/补录场景齐备）。
- 驱动：Playwright 精确 viewport（isMobile、deviceScaleFactor=2、fullPage+sips 兜底），
  每步截图 → 判读 → 记 issue（docs/ux-review-r38/）。
- 迭代：修复 → 该动线全步复测 → 下一动线；全部通过后部署公网 + 手册截图同步 +
  严苛 subagent 终审（用户验收标准：无明显交互/视觉问题）。
