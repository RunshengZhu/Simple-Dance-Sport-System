# E2E 测试标准 v1.0（全端全赛制）

> 制定：2026-09-06，依据 REQUIREMENTS v0.2.4 / DESIGN v0.2.4 / WALKTHROUGH v1.2 /
> Round 9 外网 E2E 14 项 / Round 11-12 压测不变量。
> 适用对象：正式部署 http://59.110.90.21:8321（feat/service-core d66aed3+）。
> 执行方式：浏览器真实 UI 动线（视口模拟）+ API 并发压测 + 容灾注入，混合证据。

## 0. 目标

以完全的体育舞蹈赛事运行标准验证：**所有环节合理、有一定容灾能力**。
即三类角色 × 三类设备 × 全部评分类型 × 多轮次晋级 × 团体总分 × 大屏控制 × 容灾恢复，
每个检查点有可复核证据（DOM 断言 / 截图 / API 响应 / 独立对照计算）。

## 1. 设备与视口标准（front-end E2E 必须按此模拟）

| 端 | 视口 | 断点档 | 代表页面 |
|----|------|--------|----------|
| 裁判（手机） | 375×812 | <720 单列 | /login、/judge、/judge/competition-events/{ceid}/dances/{dance} |

每个动线批次结束后关闭本批次全部标签。

## 2. 数据集标准（最复杂赛事）

在一个新建赛事（命名 `E2E全栈赛-<日期>`）中同时覆盖：

- **8 单位**：北京大学/清华大学/复旦大学/南京大学/浙江大学/上海交通大学/武汉大学/中山大学
- **选手规模**：双人 ≥48 对（STD 16 对 101-116 + LAT 12 对 201-212 + 各项目复用）、
  集体队 8 支（T01-T08，8 单位全覆盖）；跨单位双人 ≥4 对（主报单位归属校验点）
- **裁判 9 名**：J1-J9（并发评分下限）
- **评分类型三态全覆盖**：
  - SKATING 顺位法：单人轮 + 决赛轮 + 多舞种分表
  - MARK 布尔票：预赛用法（裁判只对选中选手给 mark，提交=整体替换，部分子集合法）
  - SCORE 0~10 评分制：集体项目 F1（一位小数校验）
- **多轮次链**：≥2 个项目含 R1→决赛 晋级回填（蛇形）；
  ≥1 个分组大项目（同项目分 A/B/C 组 → 合并 → 复赛 → 决赛，验证跨组合并晋级）
- **多舞种场次**：≥1 个场次含 ≥2 舞种（裁判分舞种提交）
- **四态混排**：published / calculated / scoring / pending 各有分布
- **团体总分**：名次赋分口径（r1~r8=9,7,6,5,4,3,2,1），最末轮计分；
  独立脚本重算 vs API 逐单位对照

数据生成复用 `tools/sim_robustness.py` 的生成器（50 场次版），
浏览器动线所需「scoring 态保留场次」在 API 驱动阶段刻意保留。

## 3. 检查点矩阵（通过判据）

### A. 管理员桌面（1440×900）——10 项

| # | 检查点 | 判据 |
|---|--------|------|
| A1 | 登录 | admin 口令登录成功，进入赛事列表；错口令 401/错误提示 |
| A2 | 建赛+激活 | 新建赛事成功；激活后旧赛事自动停用（Q6 单运行语义） |
| A3 | CSV 导入 | 选手/裁判/赛程/mark 组四类导入成功；错误数据产生逐条校验报告（FR-B6） |
| A4 | 赛程编排树 | 50 场次项目树渲染，四色状态标签正确；添加/编辑/删除（pending 保护）可用 |
| A5 | 开场控制 | pending→scoring；未激活/非 pending 拒绝（400） |
| A6 | 控制台 | 进度矩阵实时（SSE）；收齐自动计算 auto_calculated:true；结果表+分舞种表渲染 |
| A7 | 评分退回 | calculated→scoring，结果清空，裁判端 SSE 通知刷新（危险操作二次确认） |
| A8 | 晋级确认 | 预案预勾选前 N；跨组合并（A/B/C→合并数正确）；蛇形回填下场 roster |
| A9 | 发布/撤回 | published→公开页+大屏可见；撤回双向隐藏；重发恢复 |
| A10 | 导出/备份/明细 | Markdown+打印 HTML 导出；备份 API 落盘；明细/滑冰判定表仅管理端（无会话 401） |

### J. 裁判移动端（375×812，浏览器真实操作）——9 项

| # | 检查点 | 判据 |
|---|--------|------|
| J1 | 直达登录 | /login?role=judge&judge=J1 自动预填，登录进入工作台 |
| J2 | 工作台 | 场次卡片列表+状态徽章（9 场），已评✓标记 |
| J3 | SKATING 表单 | 名次下拉 1~N；提交后锁定；重复名次服务端 400 |
| J4 | MARK 表单 | 勾选子集（非全员）合法；「已选 X/N」计数；提交后按每裁判收齐判定 |
| J5 | SCORE 表单 | 数值 0~10 一位小数；非法值(11/9.25)服务端 400 |
| J6 | 多舞种 | 同场次分舞种分别提交，进度按舞种独立 |
| J7 | 收齐自动计算 | 最后一名裁判提交后 auto_calculated:true，场次关闭（重交 400） |
| J8 | SSE 实时 | 他裁提交/管理退回/开场，工作台与表单页秒级刷新（<2s 目标） |
| J9 | 9 裁判并发 | 9 会话同场并发提交（API 层）全 200，无 5xx，结果唯一正确 |

### R. 负载与一致性（API 层）——5 项

| # | 检查点 | 判据 |
|---|--------|------|
| R1 | 压测基线 | ≥2000 请求、0 应用 5xx、0 连接异常 |
| R2 | 异常注入 | 空名单开场/pending 提交/非法裁判/无会话/错口令/越界值/关闭后提交 全 4xx |
| R3 | 观众负载 | 30 并发观众 120s+（HTML/API/SSE 短连混），服务稳定 |

| R5 | 结果对照 | 抽样场次结果 vs 独立重算（顺位法/Mark 票/评分制三类型各≥1）逐位一致 |

### D. 容灾——5 项

| # | 检查点 | 判据 |
|---|--------|------|
| D1 | 评分中断重启 | 部分裁判已提交→服务重启→已提交评分完整保留；未提交裁判重新登录可继续 |
| D2 | SSE 断线恢复 | 重启后裁判页/公开页/大屏自动重连（降级轮询兜底），无需人工刷新即恢复实时 |
| D3 | 优雅关闭 | restart 耗时 <15s（SSE 挂连接不卡死，Round 13/14 修复回归） |
| D4 | 数据备份恢复 | /api/backup 落盘文件完好；SQLite WAL 无 -wal 残留损坏 |
| D5 | 状态机保护 | 重启后所有场次状态与重启前一致；进行中场次可无损继续收齐并计算 |

## 4. 通过标准（Gate）

1. A/J/P/S/R/D 全部检查点有证据且通过（允许非阻塞瑕疵，须记录并评级）
2. 全程 0 应用 5xx；0 数据丢失；0 权限泄漏
3. R4/R5 对照 ALL MATCH
4. 发现缺陷 → 修复 → rsync 部署 → 受影响检查点回归 → 全绿后才可结轮
5. 每轮产出：docs/e2e/RUN-<n>.md 运行报告（检查点逐项结果+证据索引+缺陷清单），
   关键截图存 docs/e2e/shots-<n>/
