# 可用性严苛 Review R30（2026-09-07）

> 方法：基于实机截图逐动线走查（shots/ 目录 19 张）+ DOM 实测（导航溢出、查询卡、表格横滑、
> 16 人半检录、空赛事）。视角：易用性 × 各终端适配（手机 375 / 桌面 1440 / 大屏 1080p）× 边界条件。
> 循环协议同 R24：本轮给出建议与分级，整改后复核收敛。

## 0. 实测确认的「已达标项」（后续迭代不得回退）

- 检录门禁双端联动：16 人半检录场景，裁判端 8 灰 8 可评、灰行点击无效、服务端拒绝，恢复检录即时解除
- 盲评原则：裁判端全程无姓名/单位；管理员控制台正常显示（信息分层正确）
- 裁判双模式（顺序点选/直接指定）与吸附提交栏；未检录行 red hint 醒目
- 空态文案：staff 双区（暂无待赛/暂无已完成）、公开页（暂无已发布成绩）干净明确
- 大屏单屏无滚动 + 单场次公告轮换 + 冠军行金色强调
- 检录台 16 人芯片网格（4/行）触控目标充足，检录进度徽章实时
- 背番号查询：有号/无号/空赛事三态均正确

## 1. 发现与优化建议（按优先级）

### P1 —— 强烈建议本轮实施

| # | 终端/动线 | 发现（证据） | 优化建议 |
|---|-----------|--------------|----------|
| A1 | 桌面·管理员控制台 | 上场选手管理为**单列**勾选列表（d-console.png），16 人占满首屏 ~720px，1440 宽仅用 ~40%；裁判进度与结果区沉底 | ① 花名册改 3~4 列网格并支持折叠；② scoring 态时「裁判提交进度」置顶（当前排首位的是上场名单管理） |
| N1 | 手机·全部页面 | brand「体育舞蹈评分系统」在 375px 下 2~3 行竖排换行（m-admin-schedule.png 等），与右侧内容挤压 | ≤480px：brand 缩短为「评分系统」或字号降档；nav 行高收紧 |
| N2 | 手机·管理员二级页 | 导航横向可滚动但**无可视提示**（实测 scrollWidth 578 vs 231），结果中心/团体总分/大屏控制/操作手册在屏外不可发现；且赛程/控制台等二级页**无退出入口** | ① 右缘渐隐遮罩提示可滑；② 高频页（结果中心）排首；③ 二级页 nav 统一补「退出」 |
| S1 | 手机·检录/主持台 | 27 张场次卡**无筛选/搜索**，主持人找本场需长距离翻页（run_seq 未设时排在最后更难找） | 复用状态筛选 chips（待检录优先排序）+ 顶部场次编号快速跳转 |
| A5 | API 健壮性 | `open` 接口 roster 传**逗号字符串**会按字符逐个入库（实测产生 "1","0","1",… 垃圾名册；UI 发数组所以未触发）| 服务端兼容逗号字符串（str→split）或 422 拒绝非数组；入库前校验背号存在于选手库 |

### P2 —— 建议排期

| # | 终端/动线 | 发现 | 优化建议 |
|---|-----------|------|----------|
| J2 | 手机·裁判评分 | 已检录(白)与未检录(灰)行对比度偏弱（m-judge-gray-boundary.png），快速滑动时易误点 | 灰行加深底色/加锁形图标；点击灰行给一次性 toast「该选手未检录」 |
| S2 | 手机·检录台/公开成绩 | 成绩表 4 列在 375px 下横滑（实测 544/288）但**无滑动提示**，选手/队伍列首屏被切 | 卡内表格右缘渐隐 + 首次出现时的滑动提示；或 375 下隐藏背番号列只留名次/姓名/总分 |
| A2 | 桌面/手机·控制台 | 控制台花名册**不显示检录状态**——评分中裁判"点不动某背号"时管理员无从判断原因 | 花名册行加只读检录徽章（绿/灰）|
| A3 | 手机·空赛事 | 新建赛事首屏 = 防连场面板 + 状态筛选（尚不可用），真正的第一步（导入/添加场次）沉底（m-empty-schedule.png） | 0 场次时显示「三步开始：导入→编排→开场」引导卡，隐藏高级面板 |
| L1 | 手机·公开查询 | 查询按钮与输入框贴边拥挤（实测未截断但视觉贴边）；查询结果「参赛项目」为斜杠长串 | 行内右距 +2；项目改徽章流式布局 |
| N3 | 手机·staff 页 | 角色标签「检录长 / 检录员」竖排逐字换行（m-staff-16chips.png）| 角色标识移入 h1 徽章，nav 内不重复 |
| J3 | 手机·裁判工作台 | 待评/已评混排无计数，找下一场需滑行扫视 | 顶部加「待评 N 场」徽章；待评排前、已评折叠 |
