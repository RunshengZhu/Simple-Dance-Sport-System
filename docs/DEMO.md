# 示例赛事（演示）· 使用指南

线上常驻一个功能全覆盖的示例赛事，供试用者以各角色登录体验。本文档记录演示账号、
覆盖的功能点与重建方法。

**演示入口：https://dancetkt.com**

- 公开赛事中心：https://dancetkt.com/competitions （全部激活赛事的卡片列表）
- 示例赛事首页：https://dancetkt.com/competitions/51 （公开详情 + 各角色登录入口）
- 示例赛事登录页：https://dancetkt.com/competitions/51/login

> 登录即把浏览器会话绑定到该赛事；裁判旧书签 `/login?role=judge&judge=J1` 仍可用
> （自动 302 到所属赛事的专属登录页）。

## 演示账号一览

| 角色 | 登录方式 | 口令 / 链接 |
|------|----------|-------------|
| 赛事管理员 | 登录页 → 角色「管理员」→ 用户名填 `demo-admin` | `DemoAdmin2026` |
| 检录长/检录员 | 登录页 → 角色「检录长 / 检录员」 | 用户名 `demo-checkin` / 口令 `DemoCheckin2026` |
| 主持人 | 登录页 → 角色「主持人」 | 用户名 `demo-host` / 口令 `DemoHost2026` |
| 裁判 | 免口令直达（无需口令） | `https://dancetkt.com/login?role=judge&judge=J1`（J1~J7 均可） |
| 观众 | 免登录 | `https://dancetkt.com/public/results` |

> 总管理员（环境口令）仅开发者持有，不随演示发放——赛事管理员账号被钳制在示例赛事内：
> 不能删除/激活其他赛事、不能管理用户、不能改全局大屏、不能库级导入导出。

## 示例赛事覆盖的功能点

| 场次 | 类型 | 状态 | 演示点 |
|------|------|------|--------|
| W1 华尔兹单项赛 | 顺位法 | 待开始 | 控制台「开启评分」全流程、赛程编排里的编辑/删除 |
| P1 标准舞预赛 | 顺位法（12人） | 已发布 | 预赛 → **晋级确认**（6 人回填 P1F）→ 决赛的完整链路 |
| P1F 标准舞决赛 | 顺位法（6人） | 已发布+已播报 | 结果中心发布/撤回、主持人播报标记、观众成绩页 |
| L1 恰恰预赛 | **Mark 制**（12人） | 评分中，**部分检录 8/12** | 检录台逐个点名/批量检录；裁判端未检录背号灰显 |
| R1 伦巴决赛 | 顺位法（8人） | 已发布、**未播报** | 主持人「标记已播报」演示位 |
| S1 集体舞决赛 | **评分制**（0~10 分） | 已发布+已播报 | 评分制裁判输入、名次自动计算 |

另有：团体总分页（6 个单位竞争）、锚点条/背番号查询/大屏轮播（评分中→成绩→总分榜）。

## 各角色体验动线

- **赛事管理员**：登录后直达示例赛事的赛程编排页 → 导入页（下载 CSV 模板 → 上传）→
  赛程编排添加/修改场次 → 控制台开启 W1 → 结果中心发布 R1 → 大屏控制查看（全局设置除外）
- **检录**：登录后对 L1 把剩余 4 个灰背号点绿，观察裁判端 J 直达链接实时解锁
- **裁判**：打开 J1 直达链接 → 恰恰预赛给 Mark（勾 8 个）→ 提交；W1 开场后按名次点击评分
- **主持人**：登录后对 R1 展开成绩公告宣读 → 点「标记已播报」
- **观众**：公开赛程看状态、公开成绩看名次、背番号查询输 `101`、团体总分看单位榜

## 重建

演示数据可随时一键重置（删除同名赛事后全量重建，约 1 分钟）：

```bash
python3 tools/build_demo_showcase.py https://dancetkt.com <总管理员口令>
```

脚本同时创建/修复三个演示账号；演示管理员账号绑定重建后的示例赛事。
